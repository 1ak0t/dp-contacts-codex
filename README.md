# dp-contacts-codex

Справочник сотрудников: React + REST API + MongoDB.

## Размещение через IIS: http://192.168.10.119

Если интерфейс размещён в IIS на порту 80, запросы `/api/*` необходимо
проксировать в Node.js. Иначе IIS возвращает HTML с кодом 404, а интерфейс
показывает `Unexpected token '<'` при чтении JSON.

1. На сервере установите IIS URL Rewrite и Application Request Routing (ARR).
   В IIS Manager выберите сервер → Application Request Routing Cache →
   Server Proxy Settings → Enable proxy → Apply.
   [Инструкция Microsoft](https://learn.microsoft.com/en-us/iis/extensions/url-rewrite-module/reverse-proxy-with-url-rewrite-v2-and-application-request-routing).
2. Выполните `npm ci` и `npm run build` в корне проекта, затем те же команды
   в `restapi`. Файл `public/web.config` автоматически попадёт в `dist`.
3. В IIS задайте физическим каталогом сайта корневой `dist` либо скопируйте
   его содержимое целиком в каталог сайта, включая `web.config`.
   Если на сервере уже есть собственный `web.config`, сохраните его копию
   и объедините настройки; правило `Contacts API` должно стоять перед
   правилами перенаправления на `index.html`.
4. В существующем `restapi/.env` задайте `HOST=127.0.0.1`, `PORT=4000` и
   добавьте `http://192.168.10.119` в `CORS_ORIGIN`. Настройте MongoDB и
   учётные данные, как описано ниже. Изменение `.env.example` само по себе
   не обновляет ваш `.env`.
5. Запустите `npm start` из `restapi` и настройте постоянную работу процесса
   средствами ОС. После изменения `.env` или сборки API перезапускайте процесс.
   IIS должен разрешать анонимный доступ к API; права на изменение контактов
   проверяет приложение через JWT.
6. На сервере проверьте `http://127.0.0.1:4000/api/health`, затем с клиентского
   компьютера — `http://192.168.10.119/api/health`. Оба должны вернуть
   `{"status":"ok"}`. Затем проверьте `/api/contacts` и вход через интерфейс.

Для клиентов нужен доступ к порту 80. При этой схеме Node.js и MongoDB
доступны локально серверу. Копирования одного `dist` недостаточно: процесс
REST API и база MongoDB также должны работать.

Диагностика: 404 от IIS на `/api/*` — не применяется правило проксирования;
502 — проверьте доступность Node.js на порту 4000; 500.19 — проверьте модули
IIS и конфигурацию; JSON с ошибкой на `/api/contacts` — смотрите журнал API
и подключение MongoDB. Health не проверяет подключение к базе.

## Размещение напрямую через Node.js: http://192.168.10.119:4000

Интерфейс и API обслуживает один Node.js-процесс. Адрес для пользователей:
**http://192.168.10.119:4000**. Этот IP должен быть назначен серверу;
клиентским компьютерам нужен сетевой маршрут к нему.

1. Скопируйте проект на сервер. Установите Node.js, совместимый с зависимостями
   проекта, и обеспечьте доступ к MongoDB.
2. В корне проекта выполните:

   ```sh
   npm ci
   npm run build
   cd restapi
   npm ci
   npm run build
   ```

3. Создайте `restapi/.env` по образцу `restapi/.env.example` (существующий файл
   не перезаписывайте). Настройте `HOST=0.0.0.0`, `PORT=4000`, `MONGO_URI`,
   `MONGO_DB_NAME`, `AUTH_LOGIN`, `AUTH_PASSWORD` и случайный `JWT_SECRET`.
   Замените демонстрационные пароль и секрет перед сетевым запуском.
   В `CORS_ORIGIN` должен присутствовать `http://192.168.10.119:4000`.
4. Из каталога `restapi` запустите `npm start`. Для постоянной работы настройте
   автозапуск этого процесса средствами ОС с рабочим каталогом `restapi`.
5. Разрешите входящие TCP-соединения на порт 4000 в брандмауэре сервера для
   нужных клиентских сетей. MongoDB не требуется открывать пользователям.
6. С другого компьютера откройте `http://192.168.10.119:4000/api/health`
   (ожидается `{"status":"ok"}`), затем главную страницу. Проверьте загрузку
   контактов и вход администратора. Health проверяет HTTP-сервер, но не MongoDB.

Данные хранятся в MongoDB, а не в сборке сайта. При переносе базы отдельно
перенесите её резервную копию либо укажите адрес существующей базы в `MONGO_URI`.
Сохраните старую базу до проверки переноса.

Если ранее задавался `VITE_API_URL`, удалите старое значение с `127.0.0.1`
и пересоберите интерфейс. По умолчанию запросы идут на `/api` того же сервера.

Адрес 192.168.10.119 предназначен для локальной сети. Доступ из интернета
требует отдельной настройки внешнего адреса, маршрутизации и HTTPS.

## Локальная разработка

Запустите `npm run dev` в `restapi` и в корне проекта в разных терминалах.
Vite проксирует `/api` на `127.0.0.1:4000`. Для временной проверки Vite из сети:
`npm run dev -- --host 0.0.0.0`. Для постоянного размещения используйте сборку
и `npm start` в `restapi`, как описано выше.
